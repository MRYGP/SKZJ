## 一、先定一个反直觉的及格观

AI 助力下，老杨的"简单制作经理"**不是从白纸造，是当判真闸 + 拍板闸**。AI 扛生成与工程，你退到闸上。

**及格 ＝ 真实性基线没破 + 判真闸真的开过火 + 终审锚判据过 + 出口接了真人。** 不是"好看"。

这把及格门槛从"会造"降到"会否"——而"会否"恰好是护城河本体（判真），方向对。

### 唯一的大风险（焊为护栏）
让 AI 生成、你只判，**比你自己挖更难判真**：AI 已经把料磨成光滑可信的样子，你判的是成品，最容易被"漂亮的新合理化"骗过。
> **护栏**：AI 交给你判的东西，必须**带破绽、并把客户原话贴在升华旁边**，不许只递光滑成品。（金句蒸馏 §〇·乙③「要求标不确定」+ 产线焊点 2/3 已要求。）

## 三、四个 AI 面的分工

- **chat-Claude**：判断 / 内容层（0 / 2 / 4 / 5 + 全程递质疑把手）。
- **子 Project harness**（观众 / 写手 / 对撞）：写评分离的车间（3 / 6）。
- **Claude Code**：工程与编排面（跑 6 的循环 + 装 8 的 H5 + 仓操作）。
- **Codex**：档案室（落盘 + git + 工单执行）。
- **老杨**：只站 **1（采）、7（判真）** 和四道拍板闸（0/3/4/9 + "够了停"）。

## 四、两个新零件（仓里没有，本次新增）

### ① Claude Code ＝ harness runner + H5 装配工
今天那条 `多project` 产线是你**手动在几个 Project 间复制粘贴**流转的。Claude Code 能把它脚本化：用观众/写手/对撞那几份系统指令骨架当 prompt 调 API，自动跑"润→测→再润"循环、收体感、路由给写手、装配 H5。
> 这正是降你手动负载的那个"AI 助力"——把机械编排从你身上拿走，你只留在闸上。
> 〔探针·待技术核〕观众/写手现是 chat Project，Claude Code 按 API persona 跑它们的接线方式我没验过，归技术线；先别当已落地能力排进度。

### ② #2 要"人采 + AI采"双跑取数
别把 intake 交给 AI（SOP §五.7"绝对要有一个人"），且 #2 是可迁移性验场，你要一份**干净的人采基线**。
但同一个客户**让 AI 采访 GPT 并行采一遍**，对比细节密度掉多少——这就是 SK 提的那个取数，一次拿到，直接回答"AI 采能不能用于 #3"。
> 准确说不是"别用 AI 采"，是"**#2 别信 AI 采、但要并行跑它来取数**"。

## 五、护栏 + 及格自测四条

**判真做成一张边界样本 checklist**（漂亮但偏离 / 粗浅但该留），#2 现在就用；它同时是写手#1 上岗前那份"标注规范校准协议"的种子——别等招人才建。

**及格自测四条**（每出一个副本对一遍）：
1. 每个屏上事实回得去客户原话，或标【合成】；
2. 判真闸驳回过至少一条 AI 升华——**一个从不说不的闸不是闸**；
3. 终审锚判据过（北极星三反应 / 三柱子 / 事实纪律 / 世俗化红线）；
4. 出口真的接了真人，不是"AI 都满意就发"。
