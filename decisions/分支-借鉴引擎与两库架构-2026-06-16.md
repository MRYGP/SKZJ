# KAIROS 借鉴引擎 · 产线设计判断

## 〇 · 核心原则（美感从哪来）

**美感/韵律不可凭空生成，只能从真金句、真传记文本里借，再由人取舍。**

- 真文本＝美感的**源**（经典句的韵律、真传记的肌理）。
- Claude＝**检索 + 结构 + 判断**（认型、提本意、找近似、逼结构件），**不负责冷起原创美感**。
- 中文 LLM＝**remix 助手**（按真范例的节奏意象改写候选）。
- 杨＝**品味与取舍的最终闸**（机器给候选，美感由人定）。

> 推论：凡"Claude 直接蒸一句金句 / 直接写一段旁白"而没经过"调真文本范例"，产出就会"意思对、缺美感"。这是 001 的病根。

## 一 · 借鉴引擎（两条线，同一机制：本意→中间层→近似→共构）

两库本质都是**检索底座**，不是清单。给定主人公一段语料，按意义到大库找该借的，再共构。区别只在检索键。

### 金句线（"看本意找近似再共构"）

1. **提本意**：这段语料在说哪条定律？（水杯→定律一·堕落的无摩擦）
2. **调近似**：从大库取该定律下几条**经典三级句**（古今中外把"无摩擦滑落"讲得最好的那几句）。
3. **以近似共构**：近似句干三件事——校高度（该升到多普世）、防撞车（你的句太像某名句就改）、给料（remix 其韵律意象）；再三级蒸馏出**主人公自己的**那句。

> 上轮我给的"多维候选"只走了第3步的"蒸"，**跳过了第2步"调近似当靶"**——所以缺美感。引擎没接。

### 传记线（"需要真传记文字去构建"）

1. **认型**：哪个手法族 / 真机制？（水杯→顿悟型，**非**砸冰箱的决断-物化型，见§二）
2. **调近似**：从大库取**同结构件**的真传记/真事场景。
3. **借机制不借事实**：借它"让那一刻可进入/可信"的招，套到主人公身上；事实绝不挪用。

> 库里存的必须是**从真传记文字抽出的结构件**，不是手搓样板。现在的3条只是种子。

## 二 · 活案例：砸冰箱误配（为什么必须按真机制检索 + 人取舍）

- 抽取样板把**张瑞敏砸冰箱**"可借给"标给了 001 水杯。**这是错配。**

- 砸冰箱内核＝`抽象决心 → 不可逆的肉身动作 + 当众亲历执行`（**主动、设计、staged**）。

- 水杯内核＝`一个微不足道的感官瞬间（差一寸没够到杯子）→ 突然的顿悟重构 → 人生转向`（**被动触发、私人、瞬间**）。

- 两者只在"觉醒/转折"这个**粗标签**上像，真机制相反。凭粗标签检索＝假阳性。

- 水杯的真同型

  ：

  - **乞丐看阳光顿悟**（杨记忆中真人真事，待研究方核实采真文本）：街头乞讨的年轻人，某天看见阳光照在每个人身上，顿悟"阳光像金子、照谁都一样，我为什么不能去赚钱"，当即停止乞讨、去谋生，终成大公司。内核＝`一个日常感官景象 → 突然重构"我也可以" → 立即转向`，与水杯几乎同构。
  - **馅饼寓言**（挂脖子的饼，懒得转动而饿死）：内核＝`给"惰性"一个失真、可怕的具象`（物化/失真比喻）——这正是水杯卡7里闪过的那个画面，是该借的"把抽象状态压成可怕意象"的招。

- 结论：001 该借的是**顿悟型 + 失真比喻物化**，不是砸冰箱。库必须按真机制（顿悟型/决断型/受难型…）归档，检索按真机制匹配，**最后由杨取舍挡假阳性**。

- 连带更正：上轮我说"那一下亲手选＝砸冰箱亲历执行背书"也是硬凑——那个探针先按它自己**待下田验**，别挂砸冰箱的名。

## 三 · 技术架构（库放哪、怎么调用——大白话）

你担心"大库放不进仓库"。其实不矛盾，因为**进仓的不是原料，是提炼条目**。分两层：

### 存储

- **原料层（raw·不进 git）**：研究方 deep-research 采来的真传记原文、海量原始金句。体量大 + 有版权，**不进仓库**。放本地外置目录（如 `E:\` 下的研究目录，Filesystem 可达），或仅以"出处/链接"形式存在、不存全文。

- 提炼层（distilled·进 git）

  ：从原料抽出的

  检索条目

  ——

  - 金句线＝坐标条目：定律 + **经典句≤15词带出处** + 释义 + 三级位。
  - 传记线＝结构件：抽取样板格式（场景速写用自己的话 + `A→B`结构件 + 可借给 + 真机制类型）。 体量小、版权安全、CODEX/Claude 可直接读、可版本控制。**这就是"大库进不了仓"与"库在仓里"不矛盾的原因。**

- **版权焊点**：现代传记（有版权）只存**抽象结构件 + ≤15词带出处引用**，绝不存整段；经典金句多属公共领域、短引可入。（这条同时解释了为何提炼层够小能进仓。）

### 检索（按本意找近似，三档按库规模递进）

- **档1·中间层人工（现在就能用，零技术）**：语料→认型/提本意→归到某定律/手法族格→取该格条目。**5定律 / 6手法族本身就是索引。**
- **档2·LLM 语义召回（库中等大）**：把"本意/结构件"+候选条目喂中文 LLM，问"最接近的 N 条"。库大就先按定律/族分块再喂（防超上下文）。
- **档3·向量检索（库很大才上）**：全条目做 embedding + 查询近似。需向量库工具、技术开销大，**留到库真的很大再说**，现在不必。

### 调用

- 提炼层在仓 → Claude/CODEX 像读现在的定律清单/抽取样板一样直接读。
- 原料层在外置 → 需要时 Filesystem 读（`E:\` 可达）；或研究方在外部检索后，**只把提炼条目回灌进仓**。
- 现阶段**不需要把大库塞进仓、也不需要特殊数据库**——档1 + 提炼层进仓即可起步。

## 四 · 缺的产线步（SOP 补丁方向）

现产线 D 步＝"直接蒸一句 / 直接定 craft"，**中间漏了"库内近似检索"**。补成： `提本意 / 认型 → 库内调近似真范例 → 杨取舍 → 共构（金句 remix / 借 craft）` 并在 D 步前置一条硬规则：**没调真范例不得定稿金句/旁白**（防"意思对缺美感"复发）。
