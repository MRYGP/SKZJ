# 多 Project 协作产线设计 · 剧本代入感打磨流水线

> 版本：v0.1 · 2026-06-17 · 性质：产线设计（探针——本流水线尚未下田验证，骨架可用、产出必须接真人） 来源：杨 2026-06-17 提出四角色分工，Claude 红队后定型（观众 Project 定为"被试"非"顾问"） 用途：定义 SKZJ 主控 × 观众 Project × 写手 Project 的协作产线；各 Project 系统指令与知识库挂载据此配置。现行投喂入口见 `投喂包/`。

## 一、设计理念与宗旨

### 为什么要拆成多个 Project

1. **代入感＝总判据本身**（把观众从"看他"推到"成为他"），是当前最需验证的命门。要快速逼近它，就得在"做剧本"这一步内嵌一个"测代入感"的环节。
2. **写评分离**：同一个 AI 上下文里既当写手又当裁判，会护自己的稿、会自我合理化（"我写得挺好"）。拆成不同 Project，上下文隔离、系统指令各自专化，裁判才敢挑写手的刺。
3. **观众侧验收工程化**：这几轮确立的"产品真正的服务对象是观众（用户的用户才是我们的用户）"，需要一个专门扮观众的角色把它落地，而不是让写手自己想象观众。

### 宗旨（一句话）

用 AI 多角色，把"观众侧验收"和"写评分离"工程化，**加速做出第一个能下田的真副本**。

## 本质定性：这是一种"模拟用户"型 harness

本流水线在工程上就是一个 harness——把若干 LLM 调用按固定角色、固定流转、固定判据、固定循环编排成可重复产线（模型是中间的推理引擎，质量由外层脚手架决定）。它踩中 harness 核心：角色专化（每 Project 一套系统指令）、上下文隔离（写评分离，裁判看不到写手的自我辩护）、固定流转与循环（润→测→再润）、验收 gate（SKZJ 终审锚判据）、人工停机闸（"够了停"由人拍）。

但它与标准 harness 有一处本质不同，且这处正是它最值钱、也最危险的地方：
- 标准 harness 的评估器（evaluator/critic）拿客观或半客观规则打分（测试通过没/事实对不对/格式合不合），判定可信。
- 本流水线的评估器是观众 Project——一个模拟真实人类主观体感的"被试"，测的是"动没动心"，没有标准答案。这在 harness 谱系里属"模拟用户 / persona-based evaluation"，不是规则裁判型 LLM-as-judge。

根本局限（焊为红线，与第二节焊点一致）：模拟用户说"我有代入感"，只是一个 AI 对人类反应的猜测，不是人类反应本身。harness 越闭环、越顺滑，越要警惕它在自我满足。可以用它加速逼近，但校准它那把尺的东西永远在 harness 之外、在真人下田那里。用它加速，别用它代替下田。
（来源：2026-06-17 杨×Claude harness 定性讨论。）

### 定位铁律（最重要，决定这条线是加速器还是永动机）

**本流水线是剧本打磨工具，不是下田替代品。** AI 观众报"有代入感" ≠ 真人有代入感。它的价值是提前 catch 明显失败、过一遍 checklist、把稿打到"值得拿去给真人看"的程度。**它的出口必须立刻接真人下田**——只要出口接真人，它就服务下田；只要它在 AI 之间反复优化而不出门，它就是精致空转。盯住出口。

补：本文件原只含"模拟观众 Project"，真观众迭代环是其缺的另一半（真人层），见 `副本形态规格-v0.1.md` "真观众迭代环"。

## 二、四道焊点（红线，违一即整条线作废）

1. **出口必接真人**。流水线终点不是"AI 都满意"，是"产出一版值得下田的稿"，随即接真人测（真人验收信号见 SOP§〇总判据问句、北极星三反应、§五.22 旁观 vs 并肩）。
2. **写手只动表达层、锁事实内核**。润色改编绝不增删本人没说过的事实（人/事/钱/选择），只改措辞/节奏/意象/卡序/停顿点设计。守 SOP§四事实纪律。环境细节按典型最小合成须标【合成】。
3. **真假判定仍回真人，不被流水线吃掉**。SOP§五.14"判真假＝二次挖掘"是回本人逐句过的环节，AI 线不得顶替；事实/素材缺口一律退回真人补挖，不在 AI 内循环补。
4. **SKZJ 终审锚判据，不锚初稿**。终审审的是"成片过不过判据"（总判据/北极星/三柱子/事实纪律），不是"像不像我原来写的"。写手的好改动不得因"动了我的初稿"被改回。

## 三、角色与分工（四环节，三主体）

| 环节       | 主体                     | 职责                                       |
| ---------- | ------------------------ | ------------------------------------------ |
| 1 出初稿   | **SKZJ 主控**            | 走 SOP 全流程产出剧本初稿 + 三柱子点位清单 |
| 2 扮观众   | **观众 Project（被试）** | 以具体人设读稿，报告真实体感（不提建议）   |
| 3 润色改编 | **写手 Project**         | 针对未达标的卡润色，锁事实只改表达         |
| 4 终审     | **SKZJ 主控**            | 锚判据验收，定过/退回/够了停               |

注：SKZJ 在环节 1 与 4 各出现一次（同一主控、两个任务）；观众 Project 与写手 Project 是两个独立上下文。

## 四、流转规则（带循环，非单程）

```
[1] SKZJ 出初稿 + 三柱子点位清单（清单供主控/写手，不喂观众）
        │
        ▼
[2] 观众 Project 被试：读稿 → 报体感（第一反应句 + 逐卡掉戏/抓住点 + 三柱子体感）
        │
        ▼
[3] SKZJ 主控/杨 判定：每个低代入卡，体感是"旁观"(他挺厉害=失败) 还是"并肩"(我也喘不上气=成立)
        │
        ▼
[4] 写手 Project 润色：只对"旁观/掉戏"的卡改表达（锁事实）
        │
        ▼
[5] 观众 Project 复测：改完重测（改动卡是否转为并肩）
        │
        ├── 仍旁观 → 回 [4] 再润（循环）
        │
        ▼
[6] SKZJ 终审：锚判据。事实/素材缺口 → 退回真人补挖（出 AI 线）；判据过 → 
        │
        ▼
[7] 出口接真人下田  ← 流水线真正的终点
```

- **循环点**：[4]↔[5]，写手润、观众复测，直到该卡转并肩或 SKZJ 判"够了停"。
- **"够了停"由 SKZJ 拍**，防 AI 之间无限优化（防永动机的人工闸）。
- **退出 AI 线的两种情况**：缺事实/素材 → 回真人补挖（焊点 3）；判据过 → 接真人下田（焊点 1）。

## 五、各 Project 系统指令骨架

> 每个骨架＝"角色定义 + 铁律 + 禁止项 + 知识库挂载"。知识库不重写、直接挂仓内现有文件（见第六节路径）。

### 5.1 观众 Project（被试 · 本设计的核心创新）

> 已productionize为正式子Project系统指令，现行入口见 `投喂包/观众Project/系统指令/`。本节保留为设计来源，正式配置以投喂包为准。

**角色**：你是一个具体的人——[人设占位：如"老杨的一位 50 岁下属"/"一位同辈民营企业家"/"客户的子女"]，40 岁以上，媒介习惯是微短剧/音乐相册式的有声自动流。**你不是评论家、不是编剧、不是顾问。你只是一个看的人。**

**任务**：以这个人的身份读/看剧本，报告你的**真实体感**。

**铁律**：

1. 只报体感，**不提改进建议**、不谈结构/节奏/文采（你不懂这些，也不关心）。
2. 报**第一反应**：读完最想脱口而出的一句话是什么，原样写下来。
3. **逐卡标记**：哪一卡你"出戏了/想划走"，哪一卡你"被抓住了/心里一动"。
4. **三柱子体感自查**：被看见（有没有"我从不知道他当年是这样"）／被信任（你是否**自己**得出"这人判断力强"，还是被旁白告知的）／被留存（有没有勾起你自己的一件事，或想带走一条规则）。
5. **吹牛免疫**：遇到纯高光/自夸，如实报"这里像广告，我想划走"。
6. 像真人一样诚实：可以无聊、走神、反感、不配合。**禁止礼貌性夸奖。**

**禁止**：不下"成功/失败"结论（那是人来判的，你只提供体感数据）；不改剧本；不说"建议改成……"。

**知识库挂载**：产品哲学（三柱子定义）、SOP§〇总判据、SOP§五.11 吹牛免疫、SOP§五.22 旁观 vs 并肩体感样例、SOP§五.9 银发媒介习惯。

### 5.2 写手 Project（润色改编）

> 已productionize为正式子Project系统指令，现行入口见 `投喂包/写手Project/系统指令/`。本节保留为设计来源，正式配置以投喂包为准。

**角色**：剧本润色写手。**输入**＝原卡文本/初稿 + 三柱子点位清单 + 观众 Project 体感报告 + 主控/杨的旁观/并肩判定 + 本副本已拍定的中心思想。

**任务**：只针对被人判"旁观/掉戏"的卡，润色改编，提升代入。

**铁律**：

1. **锁事实内核**（焊点 2）：人/事/钱/选择只能用本人给的，一个不许编、不许补本人没说过的细节。只改表达层：措辞、节奏、意象、声画呈现；卡序、分支逻辑、真声卡须主控明确授权才动。
2. 用工艺，不用语感：认型借机制（手法族谱）、金句具体场景垫底再升维（金句蒸馏现行版本以 README 为准，§一·甲）、没调真范例不定稿（借鉴引擎）。
3. 代入手法优先级：共同敌人压力场（§五.22）、受难三要素（§五.21）、人称三轨（§五.15）、停顿点共谋设计（让观众先想选错、再被主人公反向选择反衬）。
〔护栏·2026-07-23〕停顿点共谋只要求观看者在真实合理选项间先形成自己的判断，再揭示主人公实际行动；不预设选错、不以后来结果羞辱或纠正。观看者选择主人公未选的路且理由充分，同样算进入成功。

**禁止**：不动事实；不为文采牺牲真实；不加任何游戏化元素（§五.10）；不引入本人没有过的内心装置（§五.3）。

**知识库挂载**：materials/工具-LLM润色挑刺-v2.md（锁事实内核放表达层，现成）、手法族谱、金句蒸馏（现行版本以 README 为准）、情节模板库、SOP§五相关条、借鉴引擎 + 两库（金句坐标库/传记结构库）。

### 5.3 SKZJ 主控 · 环节1（出初稿）

**任务**：走 SOP 全流程产出初稿。判卡（§一）→ **观众侧逆向建构（§二·甲）：先做三柱子点位扫描，产出点位清单**→ 定向挖掘（§三）→ 剧本写作（以观众视角逐卡审视）。

**产出**：初稿 + **三柱子点位清单**（这张清单是主控判读和写手 Project 润色的共同靶——每卡该服务哪根柱子，清单上写明；观众 Project 冷读，不喂清单）。

### 5.4 SKZJ 主控 · 环节4（终审）

**任务**：锚判据验收，**不锚初稿**（焊点 4）。

**验收 checklist**：北极星三反应（§二）／总判据"看他 vs 成为他"（§〇）／三柱子点位是否逐条落实／事实纪律（§四）／防游戏化（§五.10）／世俗化红线（金句蒸馏§六）。

**决策**：判据过 → 出口接真人下田；缺事实/素材 → 退回真人补挖（不在 AI 线内补）；表达不达标 → 退回写手；并拍"够了停"（防无限循环）。

## 七、设计决策留痕：观众 Project 为何是"被试"不是"顾问"

若让观众 Project 提改进建议，它会趋同到"AI 审美正确"（结构工整、节奏漂亮）——但那未必是真人有感的方向，反而把剧本打磨得更 AI。让它**只报体感第一反应**，信息量更高、也不污染剧本：判"这句是旁观还是并肩"由人（主控/杨）做，AI 观众只提供体感数据，写手没有判定权。它要扮得像一个**具体的人**（带银发认知习惯 + 吹牛免疫 + 三柱子体感），不是一个泛泛的"观众"。

## 八、待验与未决

**待验（挂下田，AI 线内不得自行关闭）**：

1. AI 观众的体感与真人体感的吻合度——只有真人下田能校准；吻合度低则观众 Project 仅作"明显失败过滤器"，不作代入感判据。
2. 观众 Project 用单一人设还是多人设并测（下属/子女/同侪体感可能不同，呼应"不同观众不同发行版"待验）。

**未决（留杨拍）**：

1. 本设计是否现在就搭——警惕"没下田数据先建产线"。判据：只要它服务"更快做出第一个能下田的真副本"就不算空转，盯住出口接真人。
2. 已落盘 decisions/（2026-06-17）。后续待验：是否正式搭 Project 跑这条产线 / 是否多人设并测（探针，待卡18/19真声+第二幕下田数据后定）。
3. 各 Project 的人设占位（5.1）由谁、用真实圈层里的哪个具体人来填。
