## 一、音频引擎实现（v1.1 唯一真新增工程，也是最大长板）

### 四层音频模型（H5-B 数据模型按此改，废单一 per-card `amb`）

| 层                   | 字段            | 行为                                                         | 例                                                           |
| -------------------- | --------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **bed 幕级连续底噪** | `bed`（按幕设） | 进入该幕第一卡启动、**幕内持续不随切卡重起**、过幕才换；低音量 | 一二幕＝吊扇贯穿；三幕＝街市                                 |
| **sfx 卡级一次性**   | `sfx:[]`        | 进卡叠播一次、不循环                                         | 卡1收摊三重奏/卡2开工三重奏/卡6 QQ滴滴＋键盘敲三下/停/退格三下/卡12低频单音/卡18单音/卡19笔尖/卡20纸币脆响 |
| **narration 旁白**   | `audio`（沿用） | 现有按卡 activeAudio，优雅降级回计时                         | v1.1 旁白最少，先 TTS 占位                                   |
| **bgm 极少**         | `bgm`           | 大段无；仅三幕暖金低音、二幕单音                             | —                                                            |
| **silent 留白**      | `silent:true`   | **抽掉全部层**                                               | 停顿〇＝0.5s 纯静音（全片最安静）；卡21＝bed/bgm 静、只留真声 |

`pause/resume` 必须**同步全部层**（现有只同步单条 activeAudio，要扩到 bed/bgm）。 吊扇贯穿做环形（卡1收工三重奏 ↔ 卡2开工三重奏）是第一二幕的脊柱声——**bed 切卡不断是硬要求**，这条做断了环形就废了。

### 微信 / iOS autoplay 解锁（折进 H5-B，不推 T3）

- **在"开始"那一 tap 里解锁**：resume/创建 AudioContext + 播一段静音 buffer + 启动 bed/bgm 持久元素。BGM 随 tap 起。
- **narration 沿用** `new Audio()`，但**真机微信必测**：若每卡 new Audio() 被拦，改用复用元素池 / Web Audio buffer（**test-gated，被测出来才换**）。
- **被拦只降级、绝不卡流程**：逐卡 narration 在手势链里、不受影响；bed/bgm 被拦就静默降级。
- T3 只留更难那半：**旁白+bed+sfx 三轨同步精度** + 本地 ASR。

### bed 无缝循环（test-gate，别预建 Web Audio）

先用 `<audio loop>`，真机听 loop 接缝有没有咔哒。

- 没咔哒 → 就这么用。
- 有咔哒 → 二选一：①bed 做成够长的预渲染整轨（幕内不必 loop）；②**只给 bed** 上 Web Audio 精确无缝。 **不预建整套 Web Audio 图**（反永动机：数据才换枪）。

### 卡21 `fixed` 澄清（SK 点5）

卡21 同 card29 走**音频驱动**（时长由音频 `ended` 决定）。`fixed` 设为 ≈ 母本剪后实际时长，作用是**音频被微信拦掉时的降级播放时长**，不是"定第二阶段配速"——配速是另一回事，别混。

## 二、停顿〇 实现（probe-critical，全片最该做对的一处交互）

剧本探针：那一下亲手点，是否把"看他"顶成"成为他"。流程：

0.5s 纯静音 → 浮两枚身体声音触发键 → 点任一键 → 交替闪 reach/still 两次（约 400ms/帧，共约 1.6s）→ 卡住定格约 0.6s → 汇卡11。

- 触发键一：**把身子送出去**（view: `reach`）。
- 触发键二：**真的不想动**（view: `still`）。
- 点任一键都不代表他做了那个动作，只代表身体里两个声音被触发；结局由事实锁定：身子没有动。
- 不显示反馈字、不解释、不奖不罚、不走剧情分支。卡11后再进卡12，饼女人不得前置。

两画面可占位（纯色/文字）先下田，但必须保留“亲手点→交替二次→卡住”的动作链。交替+卡住是未验新机制，下田验；桌面不再继续模拟收敛。

## 四、测试与迭代（你问的"如何迭代"）

### 迭代铁律：可跑版优先、增量交付，每步都能在手机上播

1. **可跑骨架**：重生成 mainCards(v1.1 卡号重排A) + 三能力(四层音频 / 停顿〇 两身体声音触发器 / 每卡 bg) + 微信 unlock；资产**全占位**；一上来手机就能跑完卡1-22。
2. **接卡21真声**：剪 → 接入 → 回报实际时长（设卡21 `fixed`≈剪后长作降级用）。第四幕心脏，最高 ROI。
3. **接声音**：bed(吊扇/街市) + 关键 sfx + 停顿〇 留白 + 真声段静 BGM。这步要"听—调—再听"的小迭代环，调到环形可听、留白听得出——**声音是新长板，迭代主要花在这里**。
4. **接承重图**：后补，占位 → 真图（等出图账号）。
5. **真机微信过一遍** → 杨过节奏手感 → 招 2-3 真观众下田。

不许 big-bang 一次性憋大版；每个增量可在手机播、可单独回报。

### 下田只隔离一个变量（SK 点4）

这轮只验 **"你刚才是在看他，还是有一会儿你就是他"**。

- 重点验：第一幕"这有点像我"勾住没／电影草蛇灰线(梦醒反转片→水杯)能否自接／**停顿〇 那一下**／真声段代入。
- 第二阶段**默认收到卡22止或两入口静态桩**；**MediaRecorder(自述意愿)是另一个探针，这轮不做**——除非杨明说"这轮也要验自述意愿"（见 §七）。
- 招的人：代入/默化测试用目标客群(50+、看微短剧者)；"圈子炸不炸/被看见"只能用本人圈层的人。
