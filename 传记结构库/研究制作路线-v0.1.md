# 成功传记结构库 · 研究制作路线（技术实习生执行版）

> 版本 v0.1 · 2026-06-14 · 性质：边框路线图，交技术实习生执行 **第一铁律（你的活的边界）：** 你负责把料收齐、结构化、能被检索、能浮出候选。"哪段料服务哪根柱子、怎么借去抬升一个普通人的故事"——这是判断层，**不在你的活范围内**，由 Claude/杨 出。你一旦开始做这个判断，整件事的价值就漏了（见第六节第1条）。 **第二铁律：** 先证后扩——2–3 本证明方法有用，再扩到十本。不准一上来就建大管道。

------

## 一、出发点（为什么做这件事）

我们的产品把一个人的人生关键时刻，做成可第一人称进入的"副本"。判断一个时刻值不值得做，最终的母尺是**三根柱子**：

- **被看见**：薄薄一个结果背后，那段厚的过程被人看见、能进得去。
- **被信任**：让人信主人公的**判断力**（不是运气）。
- **被留存**：主人公的判断方式被观看者**内化**，成为他自己以后决策时的隐性参考。

问题：成功的传记（褚时健、富兰克林这些）凭什么能让读者读出这三种"感觉"？它们用了什么**结构动作**做到的？我们要把这些结构动作拆出来、存起来，这样拿到一个普通人的粗糙素材时，能找到"最相近的三个传记片段"，照着它的**结构**把素材抬到同样的三柱子效果。

**注意：我们要的是"结构件"，不是"金句"，更不是"把故事写得更漂亮"。** 这库是给写手借结构用的工具，是为了让"判卡过滤器"能对着三柱子持续迭代。

------

## 二、原则（不可破的边框）

1. **拆结构，不抄原文。** 我们存的是"这段为什么让人记得住"的结构梗概，不是原文段落。原因有二：原文对我们没用（结构才是资产）；以及版权（见第六节第2条）。
2. **三柱子对齐。** 每一条场景记录的存在理由，是它演示了被看见/被信任/被留存中的某一根。一条哪根都不沾的场景=噪音，丢掉。（但具体它沾哪根、怎么沾——你不判，留空给 Claude。）
3. **中国优先。** 我们的客户是成功的中老年中国人，中国/亚洲、且有"低谷→逆转"的传记优先。
4. **先证后扩。** Phase 0 在 2–3 本上证明方法产得出能用的模板，才进 Phase 1 建库。
5. **判断层与技术层分离（这就是你的边框）。** 你做：收集、结构化、打**客观**标签、按相似度浮候选。你不做：判断某段服务哪根柱子、判断像不像、判断借不借。后者是 Claude/杨 的活。
6. **反鸡汤、反美化套路。** 目标不是"更励志/更漂亮"。如果你摘的场景越来越像"名人名言出处"，就跑偏了。
7. **合法取材。** 用合法获得的书；我们做结构分析（合理使用）；绝不存储或传播整段受版权保护的原文。

------

## 三、要达到的效果（验收标准）

- **Phase 0 交付：** 2–3 本传记，先出原料清单，再对候选场景抽出约 10 条"结构件记录"（字段见第五节）。并由 Claude 拿杨的 #5 语料做一次"取 3 结构件 + 三柱子叠加 → 模板"，看产不产得出**能用的**模板。产得出 → 进 Phase 1；产不出 → 停下、写报告，不建库。
- **Phase 1 交付（以 Phase 0 成功为前提）：** 约 10 本传记的场景记录入库，并做一个检索：给一段语料描述，返回**最相近的三条场景记录**及其客观标签。
- **终极效果：** 拿到任一语料，库能浮出"最相近的三个传记片段 + 各自的结构件"，写手照着借力，把语料抬到三柱子效果。

------

## 四、阶段与里程碑

**Phase 0 · 证方法（2–3 本，手工，轻量）**

1. 选书：从候选清单里按"各打一根柱子的样"取 2–3 本。候选（Claude 给，可增删）：
   - 《褚时健传》→ 被看见（低谷极具体）＋ 极贴客群（中老年逆转）
   - 稻盛和夫《活法》《干法》→ 被留存（算法/价值观内化）
   - 《富兰克林自传》→ 被留存（"算法装进读者"的经典范本）
   - 唐浩明《曾国藩》/《曾国藩家书》→ 被信任（判断可复盘）
   - 菲尔·奈特《鞋狗》→ 被看见（过程脆弱）＋被信任
   - 吴晓波《大败局》→ 被信任（反向：败在哪种判断）
2. 取场景：通读，摘出每本约 10 个"读着心里一动"的场景，先形成原料清单。**不抄整段**，记位置 + 场景速写 + 客观抓手。
3. 抽结构件：对原料清单逐条追问"这段具体用了什么手法让人进入/相信/带走"，写成第五节结构件记录。只描述手法，不判三柱子。
4. 验证（Claude 做，不是你）：拿 #5 语料跑一次"取 3 结构件 + 三柱子叠加 → 模板"。

**Phase 1 · 建库（以 Phase 0 通过为闸门）**

- 把约 10 本的场景记录入库；做检索：输入语料描述，按场景描述/标签的相似度返回 top-3。
- 技术参考：`E:\sanxiangwendao` 已有一套 RAG，可借其模式；但**不到 Phase 1 不碰这套重活**。

**Phase 2 · 接入（不是你的建造，你只把检索暴露出来）**

- 给语料 → 库浮出 3 候选 → Claude/杨 判断像不像、怎么借 → 形成模板。

## 五、结构件记录 schema（你产出的东西长这样）

每条记录只含**客观字段**，不含柱子判断：

- `书名/作者/位置`：章节或页码定位。
- `场景速写`：用你自己的话，把这一幕写到能看出手法为止，不抄原文。
- `结构件`：这段具体用了什么手法让人进入/相信/带走。说具体动作，别说"很感人"。例：把抽象压成肉身动作 / 慢到只剩一个场景 / 用一个小物件缩进大赌注 / 用一句外人的话给压力一张脸 / 抽掉结局制造"当时不知道"。
- `场景类型`：决策时刻 / 危机 / 逆转 / 失败 / 日常 / 反思（客观分类）。
- `客观抓手`（这段为什么读者记得住，只列客观特征）：有无具体数字 / 有无对白原话 / 有无"你"式第二人称 / 有无身体感官细节 / 时间跨度是"时刻"还是"时期"。
- `主角当时的赌注`：客观事实陈述，不评价。
- `候选情节模板 + 候选人性定律`：归类线索，可多选，非定论。
- `三柱子`：**留空——这一栏由 Claude 填，你不填。**

------

## 六、最后要注意（交付前自检清单）

1. **柱子判断不是你的活。** schema 里"三柱子"那栏永远留空。你一旦动手填，护城河（判断）就从这儿漏了——这是这份文档最重要的一条。
2. **不抄原文。** 任何记录都是你的话的梗概 + 客观抓手，不存整段原文、不传播。法律线，硬的。
3. **别变成鸡汤模板机。** 如果你摘的场景越来越像"励志名言合集"，方向错了——我们要"结构动作"，不要"金句"。
4. **先证后扩，别建大管道。** Phase 0 没证出能用的模板前，不准上 embedding/RAG 那套重活。
5. **相近度只是浮候选，不是判决。** 检索出的"最相近三片段"是给人挑的候选，不自动套用；像不像、借不借，由人 judge。
6. **这库是工具，不是产品。** 它服务判卡过滤器的迭代，不替代判断，更不直接对外。
7. **交付物：** 原料清单 + 结构件记录文件 +（Phase 1）可检索的库 + 一页回执：我做了什么 / 卡在哪 / Claude 需要补什么。
