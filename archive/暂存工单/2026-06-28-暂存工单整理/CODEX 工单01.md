# CODEX 工单：核验并修正 SKZJ 仓库入口文件的远程看板镜像路径

## 1. 任务目标

对 SKZJ 仓库的入口与执行纪律文件做一次“事实源路径核验 + 必要修正”。

本工单不是产品推进，不改 001 副本，不改剧本，不改 H5，不改知识库上传文件。
重点只处理三个仓库层问题：

1. 根目录 `README.md` 是否已经写入本地看板不可达时的 GitHub 远程看板镜像路径；
2. 根目录 `AGENTS.md` 是否已经写入本地看板不可达时的 GitHub 远程看板镜像路径；
3. `KAIROS系统指令-现行备份-v2.4.md` 是否为 2026-06-26 小修补后的版本，并与 README / AGENTS 口径一致。

重要背景：ChatGPT 侧验收时看到的知识库命中结果与 GitHub 远程仓库结果可能不一致；本地仓库也可能已经更新但尚未 push。CODEX 必须以本地仓库实际内容为准先做分析，不得直接按外部描述机械修改。

5. `Project系统指令/ChatGPT主控Project系统指令-v2.4.md`

   `MRYGP/SK:ops/项目看板/KAIROS项目看板.md`
   GitHub 路径：

rg -n "KAIROS 多 Project 产线|KAIROS Project 系统指令目录|ChatGPT主控Project系统指令" . || true

## 3. 需修改文件

根据核验结果，最多只允许修改以下文件：

1. `README.md`
2. `AGENTS.md`

原则上不修改 `KAIROS系统指令-现行备份-v2.4.md`，除非本地文件不是 2026-06-26 小修补版；如需修改，必须只补远程镜像路径和小修补说明，不得改其他恒定判断内容。

原则上不修改 `Project系统指令/README.md`，除非发现它内部列出的文件名与实际目录不一致；不得因为 ChatGPT 知识库显示名问题去改仓库里的 `Project系统指令/README.md` 文件名。

## 4. 具体改动要求

### 4.1 根目录 README.md

检查 `README.md` 的“最小启动包”或动态状态说明处。

若当前只写：

```text
动态状态见 `D:\sk\ops\项目看板\KAIROS项目看板.md`
```

或类似只指向本地 D 盘看板、没有远程镜像路径，则改为包含以下完整口径：

```text
动态状态见本地看板 `D:\sk\ops\项目看板\KAIROS项目看板.md`；若本地不可达，读远程镜像 `MRYGP/SK:ops/项目看板/KAIROS项目看板.md`（GitHub：`https://github.com/MRYGP/SK/tree/main/ops/项目看板`）。
```

要求：

1. 不写入任何当前阶段、现行剧本版本、待办、挂起项；
2. 不把远程镜像说成权威源，只说本地不可达时读取远程镜像；
3. 不改产品定义、总纲、SOP、工具层列表，除非原文已有明显断链或与本次路径修正直接相关。

### 4.2 AGENTS.md

检查 `AGENTS.md` 的“执行前读什么（入口·动态源）”一节。

若它未包含远程镜像路径，则补成如下口径，保留原有 CODEX 执行纪律：

```text
状态以看板为权威活源：优先读取 `D:\sk\ops\项目看板\KAIROS项目看板.md`；若执行环境读不到本地 D 盘，则读取远程镜像 `MRYGP/SK:ops/项目看板/KAIROS项目看板.md`（GitHub：`https://github.com/MRYGP/SK/tree/main/ops/项目看板`）。当前阶段/现行版本/待办一律以看板为准；远程镜像用于不可达场景的状态辅助判断；若与本地看板冲突，报告冲突，不自行裁决。现行文件版本按主名前缀（如 `剧本-*`、`副本制作SOP-*`）查现行，禁凭本文件内列举的旧文件名或旧版本判断。
```

要求：

1. 不改变 CODEX 角色定位；
2. 不改变“只按工单执行”“回执三段式”“不自拟系统指令内容”等铁律；
3. 不写入当前状态快照；
4. 保留“本文件只写守则/入口源/执行纪律，不写阶段状态与版本号（恒定/易变分离）”这一类纪律；若原文没有这句，可补入同等意思。

### 4.3 KAIROS系统指令-现行备份-v2.4.md

检查文件头是否包含以下小修补说明：

```text
小修补（2026-06-26）：补充 KAIROS 看板 GitHub 远程镜像读取路径；不写入任何当前阶段/版本/待办快照，不升版。
```

并检查文件内是否在“对话动作”与“状态不内嵌”两处包含远程镜像口径：

```text
MRYGP/SK:ops/项目看板/KAIROS项目看板.md
https://github.com/MRYGP/SK/tree/main/ops/项目看板
```

若已包含，不修改。
若缺失，只做最小补丁：

1. 文件头补 2026-06-26 小修补说明；
2. “对话动作”中补本地看板不可达时读远程镜像；
3. “状态不内嵌”中补远程镜像路径；
4. 不升版，不改 v2.4 标题，不写入状态快照。

## 8. 验收标准

本工单验收通过需同时满足：

1. `README.md` 若原先缺远程镜像路径，已补入；
2. `AGENTS.md` 若原先缺远程镜像路径，已补入；
3. `KAIROS系统指令-现行备份-v2.4.md` 已确认是 2026-06-26 小修补版，或已做最小补丁；
4. 所有修改不包含当前阶段、现行稿、待办、挂起项；
5. 未改任何副本生产文件；
6. 回执明确区分：
   - 仓库已处理事项；
   - 本地与远程是否存在差异；
   - ChatGPT 知识库需杨手动删除的事项。

## 9. 回执格式

按固定三段回执：

### 1. 做了什么

必须包含：

- 读了哪些文件；
- README 判断结果；
- AGENTS 判断结果；
- KAIROS系统指令判断结果；
- 修改了哪些文件；
- 执行了哪些 grep / diff 检查；
- 本地仓库与远程 GitHub 是否可能存在差异，如能判断则说明依据。

### 2. 没做什么及原因

必须包含：

- 未处理 ChatGPT Project 知识库旧上传，因为 CODEX 无法操作 ChatGPT UI；
- 未改 `Project系统指令/README.md` 文件名，因为仓库内该文件不需要因知识库撞名而改名；
- 未改 001 副本、剧本、H5、点位清单、观众复测、原始语料；
- 如某个入口文件已是新口径未修改，说明原因。

### 3. commit 号或未提交原因

若有修改并提交，给 commit 号。
若无修改，说明“未提交：本地文件已符合工单验收标准”。
若有冲突未处理，说明“未提交：存在需杨拍板冲突”，并列出冲突点。
