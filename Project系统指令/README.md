# KAIROS 多 Project 产线 · 使用说明（三个子 Project 怎么用）

> 配套：`SKZJ\Project系统指令\` 下三份子 Project 系统指令（中心思想对撞 / 写手 / 观众）。 主指令是 v2.3（主 Project 用）；这三份是**子 Project 的系统指令**，各自粘进一个独立 Claude.ai Project 的"自定义指令"。 本说明含：①产线全景 ②各 Project 何时用/喂什么/产出什么 ③知识库怎么挂 ④待修订点 ⑤维护。

## 一、产线全景（谁喂谁、谁判、何时上真人下田）

核心角色五个：**主控**（SKZJ 主 Project＝杨×Claude，配 Filesystem MCP，唯一事实源）／**中心思想对撞 Project**／**写手 Project**／**观众 Project**／**真人（杨）+ 真观众（下田）**。

```
主控（按 SOP 判卡→挖语料→定要做哪个时刻）
   │  喂：语料建档件 + 这个时刻
   ▼
〔中心思想对撞 Project〕 摊切面 + 摆 N 个候选(每个五标破绽)
   │  候选交出去 →
   ├─► 异源多AI对撞(DeepSeek/Kimi…) + 真人初筛  ← 筛掉明显错的(破盲区)
   │  剩硬分歧 →
   ▼
〔杨〕 质疑 + 拍定中心思想   ←—— 北极星，下游全部服务它
   │
   ▼
主控：金句蒸馏(中心思想定稿后才做，查金句坐标库) + 出剧本初稿(按SOP/形态规格，含每卡三柱子点位清单)
   │  喂：初稿/成片冷读（点位清单不喂观众，防意图标注污染）
   ▼
〔观众 Project〕 报成片体感：逐卡掉戏/抓住 + 三柱子体感 + 吹牛预警 + 并肩/旁观
   │  体感报告 →
   ▼
〔主控/杨〕 判每张低代入卡是"旁观(失败)"还是"并肩(成立)"
   │  把判"旁观/掉戏"的卡 + 判定 + 中心思想 喂给 →
   ▼
〔写手 Project〕 只润表达层、锁死事实，把旁观卡改到并肩
   │  改完踢回 →
   ▼
〔观众 Project〕 复测"这卡转并肩没"
   │  收敛 →
   ▼
〔真人下田 n=2 起〕 真观众校准 → 数据回来再迭代(探针≠定论)
```

一句话：**对撞定北极星（中心思想）→ 主控出初稿 → 观众报体感 → 人判旁观/并肩 → 写手润掉戏卡 → 观众复测 → 真人下田。** 金句蒸馏夹在"中心思想定稿后、主控做"。

## 二、三个子 Project 各自怎么用

| Project          | 何时开                             | 喂它什么                                                     | 要它产出什么                                                 | 它绝不做                                                     |
| ---------------- | ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **中心思想对撞** | 一个时刻刚定要做、还没中心思想时   | 语料建档件 + 这个时刻                                        | 摊切面 + N个候选(每个带五标:句/强在哪/破绽/探针否/柱子+回得去哪个真事) | 不给"最终中心思想"、不蒸金句、不编事实、不自封裁判           |
| **观众**         | ①有了成片/有声画面版 ②写手改完复测 | 剧本或成片(別喂结构分析)                                     | 四段体感:第一反应句/逐卡掉戏抓住/三柱子体感/吹牛预警；分清并肩vs旁观 | 不提改进建议、不下成功失败结论、不冒充懂行、不礼貌性夸       |
| **写手**         | 人已判出"旁观/掉戏"卡之后          | 初稿+三柱子点位清单 + 观众体感报告 + 旁观/并肩判定 + **本副本已拍定的中心思想** | 只把判旁观的卡润到并肩(只动表达层)                           | 不碰事实内核、不自判自改好坏(踢回观众复测)、不加游戏化、不引入本人没有的内心装置 |

**铁的顺序**：中心思想(对撞→杨拍) → 金句(主控,中心思想后) → 初稿(主控) → 观众报体感 → 人判旁观/并肩 → 写手润 → 观众复测 → 下田。**写手永远在"人已判旁观"之后才动手；观众永远只报体感、不出方案；裁判永远是人。**

## 三、知识库怎么挂（关键操作 · 避免副本过期）

子 Project 不一定配 Filesystem MCP，读不到 D 盘仓库。所以知识库靠**上传文件**——但要守一条规矩防过期、防破"唯一事实源"：

- 可上传进子 Project 知识库的——只限"稳定纪律件"

  （不常变、是方法论底座）：

  - 对撞 Project：`SKILL-金句蒸馏.md`(§〇)、`产品哲学-需求与宪法-v0.2.md`(§三)、`副本制作SOP.md`(§〇)、`素材-收割-DeepSeek五步对撞提示词.md`
  - 写手 Project：`materials/工具-LLM润色挑刺-v2.md`、`手法族谱.md`、`副本情节模板库.md`、`SKILL-金句蒸馏.md`、`副本制作SOP.md`(§四/§五.15/.21/.22)、`分支-代入感与默化引擎.md`
  - 观众 Project：`产品哲学-需求与宪法-v0.2.md`、`副本制作SOP.md`(§〇/§五.9/.11/.22)

- **绝不上传进知识库的——"易变现行件"**：现行剧本(v1.1…)、前情提要、看板、语料建档现行版。这些**由主控在对话里喂给子 Project**（粘当前稿/当前中心思想），用完即弃，不沉淀成知识库副本。

- 理由：上传的副本会过期，撞 v2.3 零号"唯一事实源、不维护上传副本"。把"稳定纪律"和"易变现行"分开挂，副本就不会骗人。

> 若日后给子 Project 也配 Filesystem MCP（能直读 D 盘），则知识库挂载可全部改回"读仓内路径"，本节作废。当前默认按"上传稳定件 + 主控喂易变件"。
