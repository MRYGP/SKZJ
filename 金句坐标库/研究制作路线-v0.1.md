# 金句坐标库 · 研究制作路线（技术实习生执行版）

> 版本 v0.1 · 2026-06-14 · 性质：边框路线图，交技术实习生执行（与《传记结构库-研究制作路线》同结构，两条线并行） **第一铁律（你的活的边界）：** 你建的是一个"人性定律 × 经典坐标"**检索库**，用来喂金句蒸馏。你**不蒸馏、不造句、不判断哪句是好金句**——那是 SKILL-金句蒸馏 的判断层手艺，由 Claude/杨 出。你一旦开始造句或评好坏，就成了一台鸡汤机（见第六节第1条）。 **第二铁律：** 先证后扩——3–5 个人性定律证明能喂得动一次真实蒸馏，再扩。

------

## 一、出发点（为什么做这件事）

金句是产品弹道的"引信"（第一发），也是"被留存"的浓缩形态——把一个平庸事实压成一句记得住、带得走的话。

蒸馏这句话靠的是 SKILL-金句蒸馏 的三级法：**原浆**（客户自己说的浓缩句）→ **提纯**（拴在故事里）→ **升维**（蒸掉情节、对位一个经典坐标，成为脱离故事也站得住的人性定律句）。第三步"升维"需要一个**经典坐标**（叔本华讲意志、塞涅卡讲堕落、王阳明讲知行……），靠人脑临时回忆既慢又容易记错、甚至误引。

所以我们要一个库：**按"人性定律"分类、存好真·三级级别的经典句**，蒸馏到第三步时一查就有坐标可对；同时它还是一把**反鸡汤的参照尺**——让人随时能比"真三级句长什么样 vs 鸡汤长什么样"。

**注意：这个库是给蒸馏"喂料"和"对尺"的，不是用来"生成金句"的。** 生成在判断层，不在库。

------

## 二、原则（不可破的边框）

1. **建库，不造句。** 你存的是已有的经典句 + 客观标签；你不写新金句、不评客户金句好坏。
2. **公版优先。** 经典坐标优先取版权干净的老文本（叔本华/尼采/塞涅卡/《道德经》/《论语》/王阳明/《曾国藩家书》等）；不堆受版权保护的现代译文整段。
3. **按"人性定律"打标签，不按"主题/励志类目"。** 因为蒸馏是从客户的人性定律去反查坐标（例：堕落的无摩擦 / 不甘作燃料 / 路径须开创 / 第一次验证>回报 / 知行落差）。标签跟着定律走。
4. **反鸡汤是入库门槛。** 成功学口号、励志名言（"努力就会成功"那类）**不进正库**；最多单独存一个"反例库"当负样本，标注清楚这是反面教材。宁缺毋滥。
5. **先证后扩。** Phase 0 先建 3–5 个人性定律的坐标条目，证明能喂动一次真实蒸馏，才扩。
6. **判断层分离（你的边框）。** 每条坐标"它凭什么算三级而不是鸡汤"的判断，**留空给 Claude**；你只存客观字段（出处/原文/公版译文/一句话义/候选人性定律）。
7. **库 ≠ SKILL。** SKILL-金句蒸馏是"手艺"（判断层，已存在），这个库是"料"。你建料，别动手艺。

------

## 三、要达到的效果（验收标准）

- **Phase 0 交付：** 3–5 个人性定律，每个配若干条经典坐标条目（客观字段，schema 见第五节）。并由 Claude 拿杨的某个语料（#5 知行落差 / 001 水杯）做一次真实蒸馏，看库里的坐标喂不喂得动第三步"升维"。喂得动 → 进 Phase 1；喂不动 → 停、报告，不扩库。
- **Phase 1 交付（以 Phase 0 通过为闸门）：** 扩到覆盖常见人性定律的坐标条目入库 + 检索：给一个"原浆 + 人性定律"，返回**最相近的 N 条经典坐标** + **N 条结构同型的真三级句**。
- **终极效果：** 蒸馏到升维步时，一查即得坐标与同型样例可借力；反鸡汤检查有一把现成的尺。

------

## 四、阶段与里程碑

**Phase 0 · 证方法（3–5 个定律，手工，轻量）**

1. 定律清单：Claude 给起步的 3–5 个人性定律（如：堕落的无摩擦 / 路径须开创 / 第一次验证>回报 / 知行落差 / 不甘作燃料）。
2. 取坐标：每个定律下，从公版经典里找 3–5 条够"三级"的句子，按第五节 schema 记录（出处 + 原文/公版译文 + 你的一句话义）。
3. 验证（Claude 做，不是你）：拿一个真实语料跑一次蒸馏，看坐标喂不喂得动升维。

**Phase 1 · 建库（以 Phase 0 通过为闸门）**

- 扩定律覆盖；做检索：输入"原浆 + 人性定律"，返回 top-N 坐标 + 同型样例。
- 技术参考：可借 `E:\sanxiangwendao` 的 RAG 模式；不到 Phase 1 不碰重活。

**Phase 2 · 接入蒸馏（不是你的建造）**

- 蒸馏到升维步 → 库浮坐标候选 → Claude 判断对位、做升维。你只把检索暴露出来。

------

## 五、坐标条目 schema（你产出的东西长这样）

每条只含**客观字段**，不含"好坏/是不是三级"的判断：

- `出处`：作者 + 篇目/章节（公版优先）。
- `原文`：原句（公版）；若用译文，注明译者/版本，控制篇幅、不整段堆。
- `一句话义`：用你自己的话说它在讲什么人性，≤30 字。
- `候选人性定律`：它可能对应哪条定律（可多选；这是归类线索，不是定论）。
- `客观抓手`：它是否脱离上下文也站得住 / 是否在讲一条普遍人性（客观描述，不评分）。
- `是否三级 / 为何不是鸡汤`：**留空——由 Claude 填。你不填。**

------

## 六、最后要注意（交付前自检清单）

1. **不造句、不蒸馏、不评好坏。** 你一旦开始写新金句或判客户金句优劣，就成了鸡汤机——这是这份文档最重要的一条。生成永远在判断层。
2. **公版优先、不堆版权译文。** 老经典版权干净；现代译文控制篇幅、注明出处、不整段搬。
3. **反鸡汤是入库门槛。** 励志口号不进正库；要存只能进"反例库"且标明是负样本。宁缺毋滥。
4. **先证后扩，别建大库。** Phase 0 没喂动一次真实蒸馏前，不准上 embedding/RAG 重活。
5. **库喂蒸馏，不替蒸馏。** 检索出的坐标是给人升维时借力的候选，不自动成句。
6. **别和 SKILL-金句蒸馏 混。** SKILL 是手艺（判断层、已存在），这个库是料。你建料，不动手艺。
7. **交付物：** 坐标条目文件 +（Phase 1）可检索的库 + 一页回执：我做了什么 / 卡在哪 / Claude 需要补什么。
